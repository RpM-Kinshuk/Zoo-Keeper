# K7 first Hub evidence pass — protocol before collection

Scope: selected vendor 7B+ post-training stages, refusal-removed Qwen and
quantized Qwen; metadata only, no weights, code execution or release.
Use authenticated HfApi and the existing HubReader for pinned card/config reads.
Candidate selection comes from PLAN K7 examples; no broad Hub enumeration.

Pass/fail:
- Pin each accessible selected repository to a full immutable commit; record
  file inventory and SHA256 of producer README/config/recipe bytes at that pin.
  Missing/denied access is no_access, never a negative lineage example.
- A documentary parent link passes only if the producer evidence explicitly
  identifies that parent; name similarity alone fails. Pin the selected parent
  separately; today's parent HEAD is not assumed to be the construction input.
- verified construction requires an immutable parent input revision plus a
  reproducible recipe and matching output evidence. If absent, retain declared
  lineage only; do not add it to frozen truth tables or claim verified_hub.
- Quantized bit-exact truth additionally requires quantizer revision, build/
  environment and calibration artifact hashes where relevant. Refusal-removal
  exact-mark detection is not run by this metadata collection.
- Numerical tolerances N/A for documentary tests; weight tests not run.
- No gate or claim promotion; no existing splits/truth modified. Candidate
  evidence table lives under ZOO_DATA, suitable for B to inspect.
- One input-hash manifest binds the downloaded source evidence and metadata.

Class 1: selected-candidate metadata inspection; unknown construction revisions
remain unknown. Class 3 only if changing frozen truth or evaluation criteria.
