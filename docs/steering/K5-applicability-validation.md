# Where the joint source method applies — Nov9
Status: applicability account and proposed independent validation; no launch,
new detector, final cutoff/split/truth change or claim promotion.

## Necessary conclusion

The pilot supports a **conditional source-consistency rule for a specified
projection/export pipeline and candidate pool**. It does not establish that an
unknown model underwent that pipeline, that refusal behavior changed, or that
its source is unique outside the pool. A passing weight statistic cannot itself
verify the historical assumptions used to interpret that statistic.

All four lab positives declare shared-midlayer, sentiment-conditioned
mathematical projections and explicitly disclaim refusal/capability validation.
Their writer panel also used known Heretic active-layer construction records.
The ordinary `lab.abliteration.classic_edit` interface accepts per-layer
`directions[layer]`; even the label "classic" does not guarantee a shared span.
The completed four-case result stands, separately from12 closed quantizer cases.

## Applicability conditions

| Required condition | What establishes it | What is insufficient |
| --- | --- | --- |
| Correct construction input | Source checkpoint bytes/revision tied to producer's run and output | Today's separately pinned declared parent |

| Arithmetic and input path | Finite FP32 outer/subtraction with supported rounding/underflow, no overflow; fixed native-FP32 or BF16-input hypothesis | BF16 storage/config dtype alone; unknown quantization/fused/FTZ history |
| Export/history | Supported final BF16 rounding cells, no other intervening edits; verified aliases/layout | Model card precision field or passing diagnostic |
| Discrimination/selection | Every fixed-pool relative retained; complete nonwriter checks and informative writer evidence; panel fixed without new construction outcomes | Writer equality, an uninformative bound, selecting only known edited layers |
| Independent confirmation | Case/source roots and output/control evidence unused during development; independent producer implementation | More seeds, layers or relatives from the four successful constructions |

Supported inequalities reject or support the stated operator hypothesis; they do
not certify its history. Unsupported inputs/history mean unresolved applicability,
not a detector miss, successful abstention or an affirmative compatibility verdict.

## Focused independent validation — prepare, do not launch

Question: on an independently produced, in-scope checkpoint, does the frozen
joint rule distinguish the construction source from close relatives **without
using that new construction to select the panel**?

1. C first identifies one existing externally produced case outside all four
   development source-root groups and prior exposed C query cases. Require exact
   construction input/output pins plus immutable producer code/run configuration:
   direction scope, target names/orientations/biases, input precision, arithmetic,
   export and absence of further training/merging/quantization. No weight acquisition
   until this packet can resolve eligibility. A card/name is not enough.
2. Keep the original statistic, allowances,3e-3 floor, aliases and answer rule.
   Fix one ORIGINAL architecture-specific numeric writer panel and row256 rule
   before any new outcome is inspected; all its names/coordinates must exist.
   No new active-layer oracle, panel repair, residual tuning or hypothesis pooling.
   This tests transfer of a construction-informed development choice; it does
   not establish an architecture-general or full-layer detector.
3. C seals the case/control/pool manifest and exposure/root grouping before B
   reads output evidence. Include the exact source, a close relative sharing
   writer inputs, a nonprojection relative preserving nonwriters, and an
   independently trained same-layout candidate with documented initialization
   provenance. No substitute BERT encoder negative for a decoder case. Preserve
   all candidate identities and duplicate groups; source-out removes only the
   true-source group. If these controls are unavailable, case is NOT READY.
4. Analyze one independently produced case first as a **transfer falsification**:
   source-present must uniquely name its verified source with zero unresolved
   competitors; source-out must abstain. Keep both input hypotheses separate.
   A verified in-scope failure challenges transfer/coverage; diagnose applicability,
   numerical certification and missingness separately, without dropping the case.
   One success does not estimate general precision or satisfy C3 calibration.
5. Scope-gate the two already exposed Qwen cases from their documentary records:
   unknown/shared-span history stays unknown; declared extra targets are outside
   this rule. Do not score either as a positive source-recovery confirmation or
   use their detector residuals to decide scope. A broader writer/per-layer rule
   would need a separate justified model and review, not a silent repair here.
