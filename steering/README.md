# Model Zoo: database and query framework

The end product is a large, measured database **and a framework for querying it**: help people find, compare, understand and choose open models. Research must make those answers more useful and trustworthy. A paper, a collector or a lineage detector alone does not finish the project.

## Start here

- Owner: [BOARD.md](BOARD.md), a short account of progress and decisions needed.
- Doer: [WORKFLOW.md](WORKFLOW.md), [DIRECTIVES.md](DIRECTIVES.md), [DIRECTION.md](DIRECTION.md), then the next open item in [CHECKLIST.md](CHECKLIST.md).
- Independent reviewer: the same direction/rules plus the proposed test or actual evidence. Challenge the scientific question and assumptions as well as the implementation.
- [CLAIMS.md](CLAIMS.md): what is proposed, tested and approved for a paper.
- [RESULTS.md](RESULTS.md): current observations, targets, limits and original sources.
- [DECISIONS.md](DECISIONS.md): settled owner decisions and how to request a new one.
- [DATA.md](DATA.md) and [DATA-INDEX.json](DATA-INDEX.json): checked access paths, reusable measurement maps, recovery gaps and pinned archives, independent of agent memory.
- [../docs/reference/CONTRACTS.md](../docs/reference/CONTRACTS.md): technical interfaces and measurement traps.

One doer owns the whole question, with independent review at consequential points. Permanent A/B/C tracks, briefs, steward rounds and dated internal task schedules are retired. This is a full transition, not a trial. Work in the main checkouts; do not recreate track worktrees.

Latest owner instructions govern. Current scientific rules live here; historical run reports and protocols explain what actually ran and never override current direction. Keep dates/pins in evidence, and keep external paper/release targets as planning aims. Readiness, rather than an internal calendar, determines what can be claimed or released.
